# SkillHub — локальный AI-прототип

## Интерфейс Hybrid B+C+A (25 ноября 2026)

Реализованы 12 отдельных экранов по предоставленным макетам: лендинг, Dashboard, каталог Skills, Skill, создание Skill с AI, цифровые сотрудники, профиль сотрудника, база знаний, автоматизации, аналитика, активность и настройки. Общая лавандовая дизайн-система, вырезанные локальные иллюстрации и адаптивная навигация сохранены. Для компактных ноутбучных окон добавлено отдельное уменьшение высоты меню, элементов управления и карточек.

Каждый экран доступен отдельным файлом `index.html` в `pages/`: `landing`, `dashboard`, `skills`, `skill`, `create-skill`, `employees`, `employee`, `knowledge`, `workflows`, `analytics`, `activity`, `settings`. Корневой `index.html` также открывает лендинг. Внутренние переходы работают между экранами приложения.

Числа на главной и в аналитике берутся из локального состояния браузера: подтверждённые Skills, выполненные функции и журнал событий. Схема автоматизации показывает действующий путь запроса через AI и три разрешённые функции. Редактируемого конструктора, загрузки документов, корпоративных подключений и экономических метрик в этой демонстрационной версии пока нет. Для них потребуются отдельные реальные источники данных и согласованный backend-контракт.

Демонстрационный MVP на учебном профиле Алексея Смирнова. По умолчанию модель вызывается через установленный на этом компьютере **Codex CLI** и авторизацию пользователя Codex. Отдельный OpenAI API-ключ для стандартного сценария не нужен. Само приложение работает локально, но запросы модели обрабатываются сервисом OpenAI через интернет: это не локальная нейросеть и не автономный режим.

## Запуск на Windows

Нужен Node.js 20+ и установленный Codex CLI. В терминале один раз войдите в Codex командой `codex login`. Затем из папки проекта:

```powershell
npm install
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm start
```

Откройте `http://localhost:3000`. Сервер слушает только `127.0.0.1`. В `.env` по умолчанию указано `LLM_PROVIDER=codex`. При отсутствии CLI установите его, выполните `codex login` и перезапустите сервер. Codex должен иметь доступ к интернету. Название модели берётся из настроек CLI; при необходимости можно задать `CODEX_MODEL`.

### Необязательный режим OpenAI API

Можно переключить провайдера в `.env`: задайте `LLM_PROVIDER=openai`, укажите `OPENAI_API_KEY` и при желании `OPENAI_MODEL`. API оплачивается отдельно от ChatGPT Plus. Ключ читает только backend; не вставляйте его во frontend, Git или чат.

## Что делает демо

- **Рассказать о своей работе:** свободный учебный текст превращается в структурированный анализ и черновик Skill. Сотрудник проверяет и отдельно подтверждает Skill.
- **Мои Skills:** показывает встроенные демонстрационные Skills и сформированные кандидаты.
- **Запустить цифрового двойника:** помощник выбирает подтверждённый демо-Skill, задаёт вопрос при нехватке сведений и передаёт данные реальной функции приложения.

Реальные действия выполняются кодом SkillHub, не сообщением модели:

- `validate_purchase_request` проверяет заполнение заявки и введённые статусы плана и финансирования; она ничего не утверждает и не отправляет.
- `compare_commercial_offers` сортирует синтетические предложения по показанному демо-порядку: соответствие спецификации, цена, срок.
- `create_supplier_comparison` создаёт локальный CSV-файл в `outputs/`.

Порядок сравнения — только учебная иллюстрация, не корпоративный критерий. Решения, значимые для денег, права или компании, требуют проверки человеком. Реальных систем и документов нет.

## Как работает локальный режим Codex

Node.js backend запускает `codex exec` отдельным процессом. CLI использует существующую локальную авторизацию Codex, а не `OPENAI_API_KEY`. Для структурированного результата передаётся JSON Schema; процесс запускается в отдельной временной папке, в режиме чтения и с ограничением времени. Временные файлы удаляются после ответа. Код приложения проверяет выбранное действие и вызывает только одну из трёх разрешённых локальных функций. Сам CLI не получает доступ на изменение файлов проекта.

Это удобно для демонстрации на личном компьютере. Codex CLI использует лимиты учётной записи и требует, чтобы компьютер, вход в Codex и сеть были доступны. Лимит SkillHub ограничивает число запросов приложения, но не является денежным лимитом Codex. Для корпоративной эксплуатации потребуется отдельный согласованный провайдер, например локальная модель.

## Данные и ограничения

Используйте только вымышленные учебные сведения. Не вставляйте настоящие заявки, персональные данные, договоры, цены поставщиков, внутренние документы и сведения РЭСК. Приложение не может само надёжно распознать и удалить все реальные данные из текста. Backend по умолчанию локальный, без регистрации и корпоративных интеграций. Профиль и история интерфейса хранятся в `localStorage` браузера; создаваемые CSV-файлы — локально в `outputs/`.

Лимит AI-вызовов задаётся `MAX_DAILY_AI_REQUESTS` (по умолчанию 30); счётчик в памяти сбрасывается с перезапуском сервера. Размер входа ограничен сервером; каждый запуск Codex ограничен `CODEX_TIMEOUT_MS` (по умолчанию 120 секунд).

## Структура

- `index.html`, `styles.css`, `app.js` — интерфейс и профиль в браузере.
- `server/index.js` — локальный HTTP backend и API.
- `server/llm/LLMProvider.js` — общий контракт провайдера.
- `server/llm/CodexCliProvider.js` — Codex CLI по умолчанию; `OpenAIProvider.js` — дополнительный API-режим.
- `server/llm/schemas.js` — схема структурированного анализа.
- `server/skills/tools.js` — разрешённые функции и расчёты приложения.
- `.env.example` — настройки без секретов; `.env`, `node_modules` и `outputs` исключены из Git.
